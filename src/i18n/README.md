# Desktop localization

English, French, Portuguese (`pt`, written in European Portuguese) and Simplified Chinese (简体中文, `zh-CN`) are selected in Settings → App language. The first launch uses the first supported system language, then saves the selection in `coroslink.language`. The preload bridge mirrors the preference to the desktop database for native menus and file dialogs. A language change updates subscribed React components without remounting them.

Only the selected language's catalogs are loaded: `locale.ts` imports each language's `catalogs.ts` on demand, the first render waits for `initializeLanguage()`, and `setLanguage()` switches once the new catalogs arrive (immediately if they are already loaded). Never import a catalog directly from app code; that puts it back in the startup bundle. Node tests and component fixtures that switch languages synchronously import `i18n/allCatalogs` first.

Use `t("English source", { count })` with named `{{count}}` placeholders. English source text is the fallback. Add entries to the matching `fr/`, `pt/` and `zh-CN/` catalogs (`core`, `training`, `tools`, or `watchfaces`). Each scoped translator selects its own language catalog, then falls back to the selected language’s merged catalog and finally English. Call `useLanguage()` at the top of each translated React component, and include its `language` value in memo dependencies when the cached result contains translated text. Translate static option labels when they are read, rather than when a module is initialized. Each domain imports its scoped module (`i18n/training`, `i18n/watchfaces`, or `i18n/tools`) so words such as Weight and Stroke keep their context. For ambiguous words within a domain, use `t("Open", undefined, "workoutTarget")` with the catalog key `workoutTarget:Open`, so the English label stays unchanged. Pure helpers use the corresponding `trainingLocale`, `watchfacesLocale`, or `toolsLocale` module to avoid loading React. Pass `translateLabel={t}` to shared dropdowns to retain that context.

For feedback kept in React state, store `localizedText(() => t("Settings saved."))` and display it with `renderLocalizedText`. This retains the source and interpolation when the user switches languages. Keep the feedback object in toast state so a language change updates the existing toast.

Use `getLocale()`, `formatDate()`, and `formatNumber()` for presentation. Keep ISO date keys, API payloads, enum values, CSS names, React keys, filenames, exercise names, watch artwork and user/provider content in their original form. `src/units/units.ts` applies the selected number locale without changing shared conversions. Native UI translations live in `electron/localization.ts`; dialog translation preserves file paths, extensions and button indexes.

Locale matching is shared with Electron in `electron/appLanguage.ts`. `zh`, `zh-CN`, `zh-SG` and explicit `zh-Hans` locales select Simplified Chinese; Traditional Chinese locales fall back to another supported preference or English. Every `pt` locale, Brazilian included, selects Português (`pt`). Like French and Chinese, Portuguese has one catalog; it is European Portuguese and formats dates and numbers with the `pt-PT` locale. A valid saved preference wins over system preferences. Invalid saved values follow the system. To add another language, extend the shared `Language` and resolver, `LANGUAGES`, `getLocale`, scoped catalogs and native menu/dialog catalog. Run `npm run test:localization` and `npm run build`. The localization tests cover preference precedence, restricted storage, interpolation, English fallback, subscription cleanup, French and Chinese number/date/unit formatting, live switching, form state and unchanged save payloads. Chinese and Portuguese tests also audit every literal `t()` source call, require parity with each French catalog, and verify that content interpolation remains intact. English plural suffix placeholders may be omitted from Chinese and Portuguese; content values remain literal. European Portuguese uses pre-AO90 spelling: actividade, actualizar, seleccionar, directo, óptimo, capitalised months and seasons (Outubro, Primavera), and pôr-do-sol. Dates formatted at runtime keep the lowercase months `Intl` prints for `pt-PT` ("17 de outubro"); this mismatch with catalog text is accepted.

macOS permission descriptions are bundled in `build/zh-Hans.lproj/InfoPlist.strings` and `build/pt.lproj/InfoPlist.strings` (macOS uses `pt.lproj` for every Portuguese region). These operating-system prompts follow the macOS language. Application menus and file dialogs follow the live app preference. Unit conversions, clock durations, firmware language settings and stored values remain independent of the UI language.

The newer screens are now integrated. `npm run test:localization` audits literal translation calls in both French and Chinese, plus dynamic labels for routes, chart channels, overview verdicts, sport categories and tour chapters. It also runs `scripts/test-chinese-local-screens.cjs` for both languages, covering race drafts and feedback, onboarding position, route labels and tooltips, active iPhone QR codes, race captions and overview vitals. The patch in `docs/localization/zh-CN-local-screens.patch` is a historical integration artifact and should not be applied to the current source.
